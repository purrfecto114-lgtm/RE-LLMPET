# Static Check Python Launcher Design

## Goal

Make `npm run check:static` run reliably on Windows, macOS, and Linux without changing machine execution policy or requiring a platform-specific Python command name.

## Design

- Replace the hard-coded `python3` command in `package.json` with a Node launcher under `scripts/`.
- On Windows, try `py -3`, then `python`, then `python3`.
- On non-Windows platforms, try `python3`, then `python`, then `py -3`.
- Select only an interpreter that successfully reports a Python 3 version.
- Run `scripts/static-check.py` followed by `scripts/rust-structure-smoke.py` synchronously.
- Inherit standard input, output, and error so existing diagnostics remain visible.
- Stop on the first failed check and propagate its exit code.
- If no Python 3 interpreter is available, print one actionable error and exit nonzero.

## Scope

The launcher only resolves Python and sequences the two existing checks. It does not change either Python checker, install Python, alter PowerShell policy, or modify unrelated npm scripts.

## Recovery Record

After implementation, add a Chinese task record under `docs/` that:

- separates pre-existing user changes from files changed or generated by this task;
- lists the purpose of every task-owned file change;
- records known negative effects and remaining platform limitations;
- includes the exact verification commands and observed results;
- provides file-scoped, non-destructive rollback steps without changing system configuration or using broad Git reset commands.

The record describes recovery but does not automatically execute rollback operations.

## Negative-Impact Controls

- Do not modify PowerShell execution policy, PATH, Python installation, Rust toolchains, or global npm configuration.
- Probe interpreters only with a version command; do not install packages or run user-controlled code during selection.
- Keep child processes synchronous and inherit standard streams so failures remain visible and deterministic.
- Limit source changes to the launcher, its npm entry point, generated Tauri permission manifests, lint-only Rust edits, source manifest synchronization, and documentation.
- Preserve unrelated working-tree changes and identify them explicitly in the recovery record.

## Verification

The pre-fix red case is the reproducible Windows result `CHECK_STATIC_EXIT=9009` caused by the Microsoft Store `python3.exe` alias. Success requires:

1. `npm.cmd run check:static` returns 0 and both existing checkers report success.
2. `npm.cmd test` remains green.
3. `npm.cmd run gate:source` remains 16/16.
4. `node scripts/generate-source-manifest.js --verify` passes after regenerating the source manifest for the intentional file changes.

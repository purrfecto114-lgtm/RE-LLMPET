# 2026-08-03 Rust 编译与静态检查任务恢复记录

## 任务目标与环境

本任务用于消除新版 Rust/Clippy 的编译告警，并让 `npm run check:static` 在不修改本机系统配置的前提下可靠选择 Python 3。工作环境为 Windows；Rust 工具链为 `rustc 1.97.1`、`cargo 1.97.1`，Python 为 3.13.14。

本文只记录恢复方法，不自动执行回退。

```text

```

以上三项是用户在本任务前已有的工作，不属于本任务。不得恢复、删除、覆盖或归入本任务 diff。执行任何回退前必须先审核 `git status --short` 和 `git diff`，确认仍保留这两项删除及 `routine.md`。

## 本任务永久变更

### Rust lint-only 修复

- `src-tauri/src/commands.rs`：删除未调用的 `emit_stats` 和 `run_probe` helper；采用 Clippy 建议的返回表达式、`Result` 匹配、数组分隔符模式及引用传递；调整 `which` 文档注释位置。预期不改变已使用路径的运行行为。
- `src-tauri/src/hook_install.rs`：为暂未构造但作为公开状态契约保留的枚举分支添加局部 `dead_code` allow；移除无效的结构体默认展开和未使用局部变量；按 Clippy 建议简化排序与返回表达式。预期不改变安装、备份保留和回执清理行为。
- `src-tauri/src/http_server.rs`：为仍需暴露给调用方、但当前未读取的 `ServerInfo.token` 添加局部 `dead_code` allow，并说明保留原因。HTTP 行为不变。
- `src-tauri/src/metering.rs`：简化上下文窗口默认值表达式；对参数保持扁平的 `cost_for` 添加局部 `clippy::too_many_arguments` allow。计量计算意图不变。
- `src-tauri/src/model.rs`：用派生 `Default` 取代等价手写实现；为兼容测试或未来状态契约而保留的字段、枚举分支和函数添加局部 `dead_code` allow。运行时状态默认值不变。
- `src-tauri/src/pricing_sync.rs`：简化 Windows `curl.exe` 候选路径分支的返回表达式。路径选择行为不变。
- `src-tauri/src/transcript.rs`：将错误回退改写为等价的 `unwrap_or_default()`。扫描错误时仍返回默认结果。

这些修改的范围是 lint-only，但删除未调用 helper 仍可能影响仓库外部补丁、条件编译路径或未来合并，见“潜在负面影响与未验证范围”。

### Windows 静态检查兼容

- `scripts/run-static-checks.js`：新增 Node CommonJS 启动器。Windows 依次探测 `py -3`、`python`、`python3`，非 Windows 依次探测 `python3`、`python`、`py -3`；只接受 `--version` 返回 Python 3 的候选。随后无 shell、同步、顺序执行 `scripts/static-check.py` 和 `scripts/rust-structure-smoke.py`，在首个失败处传播退出码。
- `package.json`：将 `check:static` 从硬编码的两次 `python3` 调用改为 `node scripts/run-static-checks.js`。
- `test/tauri-cli-resilience-r7-smoke.js`：第 40 行把稳定入口断言从硬编码 Python 命令更新为严格断言 `check:static` 等于 `node scripts/run-static-checks.js`，使 R7 smoke 契约与启动器强绑定，防止门禁命令回退到平台相关的硬编码调用。

行为影响是 Windows 不再因 Microsoft Store `python3.exe` 占位符直接失败；实际解释器取决于平台候选顺序和当前进程继承的 PATH/Windows Python launcher。

## 潜在负面影响与未验证范围

- 新版 Clippy allow 会形成维护成本：被保留成员未来开始或停止使用时，局部 allow 和说明可能过时；升级 Clippy 后规则也可能变化。
- 删除当前无调用的 `emit_stats`、`run_probe` 等 helper 可能给仓库外补丁、未覆盖条件编译路径或后续合并带来兼容风险。恢复时应以可信基线和实际调用关系为准。
- Python 启动器按 PATH 或 Windows launcher 的候选顺序选择解释器。多 Python 环境中可能选到并非操作者期望、但版本报告为 Python 3 的解释器；非 Windows 分支尚未真机验证。
- `scripts/run-static-checks.js` 的候选顺序、Python 2 拒绝、fallback 以及失败退出码传播目前没有可控单元测试；现有证据仅为 Windows 本机 happy path 与源码审查，macOS/Linux/失败路径仍为剩余风险。本轮不新增测试，因为批准计划的范围是实际 Windows 门禁和严格 smoke 入口契约；该缺口不削弱现有验证结论。
- 项目生成器默认读取当前工作树；为避免把用户原有两项删除和 `routine.md` 带入本任务提交，提交版 manifest 必须从 task-only Git index 快照生成。提交后，当前脏工作树与提交快照不同，直接在当前工作树运行 manifest verify 会反映这三项用户状态差异；应在提交树或等价干净快照中验证提交版 manifest。
- 仅在 Windows 真机开展了本任务工作；尚未验证 macOS、Linux、bundle 打包、破坏性测试、真实 provider 集成和代码签名。
- 关于 `reports/protocol-drift.json` 的先前疑虑已澄清：`npm test` 会刷新该报告的 `generatedAt`，最终验证后已精确恢复为基线 `2026-08-03T08:24:22.624Z`；该文件现与仓库基线一致，不作为本任务永久变更，生成器 `SOURCE_MANIFEST.json` 也明确排除该报告。

## 文件级非破坏性恢复

恢复前先保全现场并审核边界：

1. 运行 `git status --short`、`git diff --name-status` 和 `git diff -- <目标文件>`，逐文件确认要撤销的内容。
2. 将当前完整 diff 保存到仓库外的安全位置，或使用团队认可的非破坏性补丁/分支方式保留；同时单独记录未跟踪文件内容。
3. 明确排除 `RE-LLMPET-0.5.22-package-regression-audit-roadmap.md`、`worklog.md` 和 `routine.md`，不得把它们加入任何本任务恢复命令。

从已审核的可信基线恢复本任务拥有的已跟踪文件：

```powershell
git restore --source=<可信基线> -- package.json test/tauri-cli-resilience-r7-smoke.js SOURCE_MANIFEST.json
git restore --source=<可信基线> -- src-tauri/src/commands.rs src-tauri/src/hook_install.rs src-tauri/src/http_server.rs src-tauri/src/metering.rs src-tauri/src/model.rs src-tauri/src/pricing_sync.rs src-tauri/src/transcript.rs
```

`package.json`、R7 smoke 契约（`test/tauri-cli-resilience-r7-smoke.js`）与启动器（`scripts/run-static-checks.js`）必须一起恢复：前两者随本条命令回退到可信基线，启动器在下方新增文件清单中一并删除，三者保持同一状态，避免出现 `check:static` 仍指向启动器而启动器已删除、或 smoke 仍断言新命令的不一致恢复。

`<可信基线>` 必须先由人工确认，不能盲目使用当前分支或不明提交。若目标文件在本任务期间又有他人修改，应从已保存 diff 中按 hunk 人工恢复，而不是整文件覆盖。

逐一删除仅由本任务新增的文件，删除前确认它们没有后续人工修改：

